# M2 計画: 値と定数評価

M2 では、TLC の値 (`tlc2.value`) と定数の評価器 (`Tool.eval` の定数レベル) を Rust で書き、`ASSUME` の評価結果と TLC の出力をバイト単位で一致させる。この文書は作業の順序と完了条件を決め、進捗を記録する。

## 完了条件

- tla-ts のコーパス `test/tlc/expressions` のうち式のケース (`flags: [expression]`) 923 件すべてについて、`assume` 文脈で tlars と TLC bc1b506 の終了コードと正規化した `-tool` 出力が一致する。照合は `xtask conformance run --check` で行う。
- 残り 61 件は文脈を持たないモデルのケース (SPECIFICATION などを使う) なので、M3 以降で扱う。
- 値の各操作 (等価、順序、所属判定、指紋、`toString`、列挙順) は、TLC から作った golden と一致する。

DESIGN.md の「expressions 984 件 × 5 context」のうち、`init`、`next`、`invariant` の 3 文脈は状態の探索 (M3)、`property` は活性検査 (M4) を必要とする。そこでこの 4 文脈は M3 と M4 の合格条件に回し、M2 では `assume` 文脈だけを完了条件にする。

## 前提として確かめた事実

- **コーパスの所在:** コーパスはこのリポジトリになく、tla-ts (`packages/conformance/test/tlc/expressions`) にある。15 のカテゴリに 984 件あり、HEAD は 9614c1c (2026-11-19 に確認)。
- **記録の版:** tla-ts の記録は tlaplus 309e489 の TLC で取られている。tlars の基準は bc1b506 なので、期待値は bc1b506 の TLC で取り直す。
- **TLC の呼び方:** 引数は `-workers 1 -fp 0 -seed 4 -lncheck final -noGenerateSpecTE -tool -metadir <dir> -config <cfg>` で、JVM は `-Xss2m` (tla-ts の `hosts.ts`)。`assume` 文脈は、モジュール末尾に `ASSUME Test` を足し、cfg を空にしたものである。
- **出力の正規化:** 正規化の規則は tla-ts の `transcript.ts` にある。変動するメッセージコードを落とし、パス、日時、所要時間、版番号を置き換える。
- **出発点:** CLI は引数の解析まで動く。`driver::process` から先 (cfg の読み込み、`load` の呼び出し、ツールの構築、ASSUME の評価) は `todo!()` で、`tlars-tool` の値と評価器も骨組みだけである。

## 方針: 値と評価器は手で書く

DESIGN.md の決定 (値は `Arc` を使い `Send + Sync`、等価と順序は失敗しうる `tlc_equals`/`tlc_compare`、正規化は `OnceLock`) を引き継ぐ。jj2rs で `tlc2.value` と `Tool.java` を変換する案は採らない。理由は次の 3 つ。

- jj2rs の出力は `Rc<RefCell<_>>` と `JResult` で、`Send` でない。M6 の並列化と M3.5 の性能の関門に合わない。
- `tlc2.value` は `tlc2.tool` の評価器、リフレクション、直列化に絡み合っていて、SANY ほど閉じていない。
- 正しさはコーパスの照合で担保できる。SANY では木の形を変換で一致させたが、M2 では観測できる出力 (メッセージと終了コード) で一致を確かめる。

## 作業の単位 (危険の大きい順)

各単位は、照合スクリプトの合格件数が前の単位より増え、既に合格していたケースが落ちないことを確かめてから次へ進む。

1. **照合の土台:** コーパスを固定版で取り込み、bc1b506 の TLC で `assume` 文脈の期待値を記録し、`transcript.ts` を移植した正規化と照合の実行器を作る。この時点の合格件数 0/984 を基準値として記録する。
2. **ASSUME までの経路:** `driver::process` の版表示、cfg の読み込み、`tlars_sany::load`、`SpecProcessor` の定数処理、`checkAssumptions`、`-tool` 形式のメッセージ出力、終了コードをつなぐ。値は真偽値と整数だけで始める。
3. **値の核:** 集合、関数、レコード、タプル、区間と、等価、順序、所属判定、正規化、指紋を実装する。指紋と順序は Java 側で作る golden で照合する。
4. **評価器:** 演算子の適用、量化子、`CHOOSE`、`LET`、`IF`/`CASE`、`EXCEPT`、関数と集合の構成子を実装し、標準モジュール (Naturals、Integers、Sequences、FiniteSets、TLC) のうちコーパスが使うものの組み込み実装を足す。
5. **エラーの文言:** 評価中の例外の文言と、「nested expressions」の位置の列 (メッセージ 2103) を実装する。
6. **表示:** 値の `toString` と、TLC の pprint (幅 80 で折り返す) を実装する。

単位 3 以降はカテゴリごとの合格件数で進捗を測り、件数の推移をこの文書の記録に残す。
